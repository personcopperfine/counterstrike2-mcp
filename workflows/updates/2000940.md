## The game change: `SosStartSoundEventParams_t` gained a member (fixed: header + sigs)
- Found by A1 (Linux `SNOFF_SEP_HASH/ENTINDEX` 0 matches) and B2 (Windows `SNOFF_SEP_HASH/ENTINDEX/FLAGS`
  0 matches, `SNOFF_SEP_PACKED_LEN` resolving to **32** instead of 28). These Windows entries carry `sdk`
  (the binary measurement of the header the bridge's sound hook reads), so a stale entry would have hidden
  a real regression: on 2000940 the bridge would read the new field as the packed-data length, the seed as
  the layer, and probe 8 bytes short of the struct.
- Evidence (read in the binaries, then confirmed by an independent Opus RE pass with objdump): CS2 2000940
  inserted a 4-byte member at +0x1C on both ABIs; `m_nFieldDataSize` 0x1C->0x20, `m_nSeed` 0x20->0x24,
  `m_nLayer` 0x22->0x26, `m_unk101` 0x23->0x27, `m_bTraceSoundscapes` 0x24->0x28; +0/+8/+0x10/+0x14/+0x18
  unchanged; sizeof 0x28->0x30 (last member read is +0x28, 8-byte alignment; no whole-struct copy proves
  the tail). Windows: slot-11 impl sub_1801C2030 (`mov eax,[rbx+1Ch]` -> internal +0BCh at 0x1801C20EF,
  `mov r8d,[rbx+20h]` len at 0x1801C2130, seed `[rbx+24h]` 0x1801C20DA, layer `[rbx+26h]` 0x1801C20D0,
  `cmp byte [rbx+28h],0` 0x1801C21A6). Linux: libsoundsystem.so 0x32f028 `mov 0x1c(%r14),%eax` -> internal
  +0xCC, 0x32f052 len `0x20(%r14)`, `cmpw $0xffff,0x24(%r14)`. Default 0: both client callers write 0
  (client.dll 0x1803AFB45 `mov dword [rsp+0x74],0` for params at rsp+0x58; libclient.so 0xF907DF), and the
  internal object's constructor zeroes its copy. Meaning not proven (one non-zero writer, a VMix voice preview
  path), so the name is `m_unk201`.
- Header: our series commit `Add ISoundOpSystem, ISoundEventManager & ISoundEventListener` (fixup + autosquash,
  the struct is ours, not upstream's): `uint32 m_unk201` after `m_Guid`, ctor `m_unk201( 0 )`, AMNOTE
  "Copied into the started sound event; callers pass 0."; message notes the 2000940 re-verification.
  allowlist `[checks]` updated to the new offsets and size 0x30 (the check is what forced this).
- Sigs: Windows block sig masks the internal layer destination (`88 87 C6` -> `88 87 ??`); Linux sigs mask the
  moved seed operands. All unique on 2000933 and 2000940; values recorded 2000940: hash 16, entindex 20,
  layer 38, packed ptr 8, packed len 32 (= the regenerated header). `via` strings carry the 2000940 sites.
