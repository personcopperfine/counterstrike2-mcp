# Model import plan (branch `import/models`)

## Evidence that changed the earlier recommendation

- `modeldoc_utils.dll` (loaded by resourcecompiler) carries `LoadOBJModel`, `LoadSMDModel`, `obj2dmx`, and the full DmeModel attribute vocabulary (`DmeModel/DmeDag/DmeJoint/DmeMesh/DmeFaceSet/DmeMaterial/DmeTransform/DmeVertexData`, `positions`, `normals`, `texcoord$0`, `jointWeights`, `jointIndices`, `jointCount`, `faces`, `baseStates`, `currentState`, `bindPose`, `skeleton`, `model`). ModelDoc file filters: Mesh/Skeleton Files = `*.dmx *.smd *.fbx`, Animation Files = `*.fbx *.dmx *.rts *.smd`, OBJ only under "Model Files". No `.gltf/.glb` string anywhere. No `.dmx` sample exists in the install; `dmxconvert.exe` only re-encodes an existing DMX (format updaters `model`, `mp_*`), so it cannot produce a reference from OBJ/SMD.
- **Decision: the intermediate is SMD, not OBJ/DMX.** SMD is plain text, carries skeleton + per-vertex weights + UV + normals + per-triangle material, and is accepted for mesh, skeleton and animation. One writer covers static, skinned and animation. DMX stays a later option (schema attribute names are now pinned from the binary, verification = "compiler accepts it + `get_model_info` shows bones"; no user reference needed) only when SMD's limits bite (one UV set, no vertex colour, no morphs).
- Prefab: `CMapPrefab` DMX keys `targetMapPath`, `fixupEntityNames`, `loadAtRuntime`, `loadIfNested`, `useTargetnameAsPrefix`, `entityIOTargetName`, `prefabRuntimeEntity` (hammer.dll attribute tables); `func_instance {file, fixup_style, replaceNN}` is a real FGD class; the bridge has no node-create method for prefabs (`entity.create` only). `src/vmap` lists `CMapPrefab` as an *unsupported* container.
- Mesh route facts: `create_mesh` takes vertices/faces/materials only, **no UVs**; the bridge initialises world-aligned texturing (`GEO_UV_MODE 2`); `mesh.setFaceTexture` supports absolute `axisU/axisV/scale` (answered per face), but the `align_texture` tool exposes only shift/scale/rotate. Caps: 65 536 verts and faces per mesh, 1 M indices, 64 materials/mesh, 512 KB per request.
- CS2 skeleton: `src/resource/model.rs` already reads `m_modelSkeleton.{m_boneName,m_nParent,m_boneRotParent,m_boneScaleParent}` from a `.vmdl_c`; shipped agents are `characters/models/<tm_*|ctm_*>/...vmdl_c` in `pak01_dir.vpk` (`src/vpk.rs`).
- ModelDoc node types include `Skeleton`, `SkeletonFile`, `NmSkeletonReference`, `RenameBone`, `ReassignBoneParent`, `DefineBone`, `KeepOnlySpecifiedBones`, `HitboxSet_Auto`, `Prefab/PrefabList` (CModelDocPrefab `m_TargetFile` = merge another `.vmdl`), so some retarget steps can live in the `.vmdl`.
- `model_compile` pins `CompileTarget::MODELDOC`; the resourcecompiler route does not need ModelDoc. Import compiles use `ANY_TOOLS` (and `model_compile` should too; small change).

## Scope and non-goals per target

| Target | In scope | Non-goals |
|---|---|---|
| **prop** (`kind:"prop"`) | glTF/GLB static or skinned → SMD + `.vmdl` (template `static_prop`/`skeletal`), FBX/SMD/OBJ/DMX pass-through (copy + template), materials from glTF PBR, glTF animations → anim SMD `AnimFile`s, physics: hull from render mesh (`PhysicsHullFile` same SMD) or none | morph targets, vertex colours, >1 UV set (reported as `dropped[]`), Draco/KTX2/other extensions (typed error) |
| **world-as-prop** (`kind:"world"`) | same pipeline, `PhysicsMeshFile` (concave) instead of hull, placed as `prop_static` via `create_props`, optional `splitByNode` (one model per glTF root node) | lightmap UV authoring, LOD generation |
| **world-as-meshes** (`kind:"hammer_mesh"`) | triangulated planar faces, chunked `create_mesh` calls by material/size, coplanar merge of convex fans only, exact per-face UV via absolute texture axes (needs the align_texture extension), materials created as in prop | non-convex n-gons, smoothing groups, displacement, instancing |
| **prefab** | a reusable `.vmap` under `maps/prefabs/<name>.vmap` in the active addon holding the import's nodes (props/meshes + any entities), instanced into a map as a `CMapPrefab` node; list prefabs; read them back | Hammer prefab variables (`$var` locators), nested prefabs, terrain prefabs |
| **player** (`kind:"player"`) | arbitrary rig → CS2 agent skeleton (names + hierarchy + rest pose of a chosen shipped agent), explicit/heuristic/structural bone mapping, bind-pose baking, weight reassignment, `.vmdl` with the agent's `anim_graph_name`, auto hitboxes, live check as `prop_dynamic`, Metamod `SetModel` route for the real pawn | editing animgraphs, facial/cloth/jiggle, first-person arms, weapon attachments beyond copying the agent's attachment list, guaranteed deformation quality for rigs far from humanoid |

## Tool surface (two new tools, budget +~2.6 KB measured, MAX raised by exactly that)

**`model_import`** (Writer; no bridge methods for the file work; the compile uses the container route):
args `source` (host path or path under the addon; `.gltf/.glb/.fbx/.smd/.obj/.dmx`), `kind` `prop|world|hammer_mesh|player`, `name` (model folder/stem; default = file stem), `scale` (default 39.37 for glTF/GLB metres, 1 otherwise), `upAxis` (`y` default for glTF; `z`), `materials` `generate|existing|none` (default generate), `physics` `hull|mesh|none` (default by kind), `compile` (bool, default true), `overwrite`, `dryRun`, and for player: `agent` (`characters/models/tm_phoenix/tm_phoenix` default), `boneMap` `{sourceBone: cs2Bone}`, `rig` hint `auto|mixamo|rigify|ue|vrm`; for hammer_mesh: `origin`, `angles`, `maxTrisPerMesh`.
result `{model, files:[{path, role}], materials:[{vmat, textures, dropped?}], mesh:{tris, verts, materials}, skeleton?:{bones, mapped, unmapped:[{bone, weightsMovedTo}], confidence}, physics, compile?:{ok, failLines}, dropped:[], warnings:[], next}`; hammer_mesh returns `nodeIDs[]`, `chunks`, `facesPerChunk`, `uvMode`.
errors (typed, `data` as noted): `UnsupportedFormat{ext, supported}`, `UnsupportedExtension{gltfExtensions}` (Draco etc.), `ImportParse{detail}`, `TooLarge{tris, cap}`, `ModelExists` (use `overwrite`), `NoSkin` (kind player on a static mesh), `BoneMapIncomplete{unmapped, required}` (player: a required CS2 bone with no source), `WrongEngineAddon`/`PathNotMapped` reused, `CompileFailed{failLines}` (files stay on disk, `next: model_compile`).
next chain: `model_compile` (only when `compile:false`) → `get_model_info` → `model_render` → `create_props {class}` → `save_map` → `compile_map` → `run_map` → `look {target:nodeID, mode:"frames"}` → `report_ready`. For player: `create_props {class:"prop_dynamic", keyValues:{DefaultAnim}}` then `look`, then `player_model {action:"set"}` (I7, cs_script route) and a client-mcp check.

**`prefab`** (Mutating; `action` enum like `cs_script`): `create {name, nodeIDs?|fromImport?, centerOnOrigin}` (saves `maps/prefabs/<name>.vmap`: a `new_map`-style fresh document from the addon template, the nodes copied as entities/meshes via existing bridge ops, `save_map`; the current document is left untouched), `instance {name|path, origin, angles?, fixupEntityNames?, targetname?}` (bridge `node.createPrefab`, see spike), `list`, `read {name}` (prefab contents through `src/vmap`). Errors: `PrefabNotFound{available}`, `PrefabExists`, `NotImplemented{missing:["node.createPrefab"]}` until the bridge ships it.

## Module layout and dependencies

- `hammer-mcp/src/import/` — `mod.rs` (format dispatch, `ImportPlan`), `gltf_read.rs` (`gltf` crate → `Scene{meshes, materials, skin?, animations}` in our own types), `smd.rs` (writer: reference/anim/physics SMD; Z-up and scale applied here), `materials.rs` (PBR → `.vmat` text via `cs2-kv1`, texture bytes written as PNG/JPG; `textures/` subfolder), `planar.rs` (triangulate, coplanar convex merge, per-face UV axes), `chunk.rs` (mesh chunking under the caps), `retarget/` (`skeleton.rs` CS2 skeleton from `.vmdl_c`, `mapping.rs` name tables + structural matcher, `bake.rs` rest-pose baking + weight reassignment).
- `hammer-mcp/src/resource/model.rs` gains `pub skeleton: Option<Skeleton>` (name, parent, local pos/rot/scale) and `anim_graph: Option<String>` in `ModelInfo`; `get_model_info` gets `include:"skeleton"`.
- `hammer-mcp/src/vmdl/template.rs` gains `PhysicsMeshFile`, `remaps` per material, `Skeleton`/`SkeletonFile`, `HitboxSet_Auto`, root `anim_graph_name`, `AttachmentList` copy.
- `hammer-mcp/src/vmap/mesh.rs` + `mod.rs`: `CMapPrefab` becomes a listed node kind (`targetMapPath`, transform), still not a mesh parent.
- `hammer-mcp/src/tools/model_import.rs`, `prefab.rs`; `tools/mesh_live.rs`: `align_texture` gains `mode:"axes"` with `faces:[{index, axisU, axisV, scale}]` (bridge already accepts absolute axes; verify in spike).
- `crates/cs2-bridge`: `node.createPrefab` (m3.18) via `CDmElementFactory<CMapPrefab>` + attach under world + undo group (needs sigs/pins: hammer.dll factory/attribute setters — RE brief), later `game.setPlayerModel` (server-side `CBaseModelEntity::SetModel` on the local pawn; sig in `sigs/signatures/libserver.json`/`server.json`).
- Dependencies: `gltf = "1.4"` with `default-features = false, features = ["utils", "KHR_materials_pbrSpecularGlossiness"]` (MIT/Apache-2.0, pure Rust; keep `image` off). Nothing else; PNG/JPG bytes are passed through to the compiler.
- Fixtures generated in-test: a glTF builder in `hammer-mcp/tests/common/gltf_fixture.rs` (cube, textured quad, two-bone skinned tube with one animation, a 20-bone humanoid with Mixamo names) writing `.glb` into a temp dir; SMD goldens compared as text; CS2 skeleton fixture = synthetic `.vmdl_c` from the existing `tests/common` KV3 encoder with a 10-bone chain.
