# Proposed protocol changes for bridge m2.20 (the packed start params on `sound.drain`)

Additive over m2.19; no major bump and **no new methods** — the only wire change is one new field
on the events `sound.drain` already reports (WP-B of the hammer sound plan, plan-snd.md §5 items
4-5; the RE facts are `target/orch/re-snd.md` R4 `[V live + V bin]` and the reference probe
`target/orch/re/probe-packed-params.diff`, whose hardcoded offsets these pins generalise):

**`sound.drain` (via 11 only) gains `"params"`** on each event:

```json
{"seq":…, "hash":…, "name":"mcp.snd.point", "entindex":0, "guid":…, "via":11, "flags":…,
 "ageMs":…, "origin":[…], "entityName":"worldent",
 "params":{"len":12,"hex":"5a7cce4d0a0c00a10b1d43…","truncated":false}}
```

- `len` is the caller's declared byte count (an `int` read at `params + SNOFF_SEP_PACKED_LEN`);
  `hex` is the **at most 128 bytes the bridge copied** (`SND_PARAMS_MAX`), lowercase hex;
  `truncated:true` when fewer bytes landed than `len` declares (the copy stopped at an unreadable
  page) — the WP-S5 decoder walks what is there and reports `decoded:false`.
- `"params":null` when the params pointer or length field itself was unreadable, or the length is
  negative or above 65535 (not a plausible byte count) — "no params seen", never an empty string.
- Events from the other wrapped slots keep their previous shape: **absent** for via 12
  (`StartSoundEventByNameWithParams` — its params pointer is not copied by the via-11 block these
  pins locate) and 13 (`StartSoundEvent`, no params at all); the via-81 listener rows never carry
  it. The per-event rollback logic is unchanged (an event is written whole or not; worst case per
  event is now ~1000 B, still far under one ring row's share of the 96 KB reply cap).

## §8 error codes

**No new codes.** A params read failure is not an error: the hook is on the game's sound thread,
must never fail a start, and degrades to `params:null` / a truncated `hex`.

## §5/§6 notes

- Method count: **84 registered / 69 implemented** (unchanged from m2.19 — no new rows).
  `control.version.bridgeVersion` and every `"build"` field are **`m2.20`**.
- **New pins** (`sigs/signatures/soundsystem.json`, `bridge_structs.h` regenerated by `pins.py`,
  following the SNOFF_SEP_* precedent — `kind=offset`, tag V, no `bridge` macro):
  `SNOFF_SEP_PACKED_PTR` (expect `8`) and `SNOFF_SEP_PACKED_LEN` (expect `0x1C` = 28), both
  located by one direct sig on the field-copy block in
  `CSosOperatorSystem::StartSoundEventWithParams` (`448b43`-style: `mov r8d,[rbx+1Ch]; test
  r8d,r8d; jle; mov rdx,[rbx+8]; lea rcx,[rdi+10h]; call sub_1801E0220`) at
  `soundsystem!0x1801C5C67` on build 2000930 — the same block the existing
  `SNOFF_SEP_HASH`/`SNOFF_SEP_ENTINDEX`/`SNOFF_SEP_FLAGS` entries read; the `disp` steps lift the
  two displacements out of the instructions, so a rebuild that shifts either field re-derives or
  fails loudly. `sigcheck.py resolve` proves the pattern UNIQUE (exactly one match at `0x1c5c67`)
  and both values against `target/game-bins`.
- **Ring entry growth**: `SndEvt` gains `int plen; u16 pcopied; u8 praw[SND_PARAMS_MAX]` with
  `SND_PARAMS_MAX 128` — 256 entries × ~136 B ≈ 34 KB more static memory. `plen` is `-1`
  (unreadable, JSON `null`) for every event the via-11 params hook did not fill (via 12/13/81
  rows, and a via-11 start whose params pointer is unreadable).
- The reference probe (`target/orch/re/probe-packed-params.diff`) hardcoded `p + 8` / `p + 0x1C`
  in the shipped text; production reads only through the pins — `bridge/test_sound_params.py
  --static` fails on a `0x1C`/`+ 8` literal in the sound section and pins.py/regenerate keep the
  committed `bridge_structs.h` honest.
- `hammer-mcp` (WP-S5) consumes `params` in `drain_sounds`: per event a `position` (from the
  `position` field hash walk) and a `params:{len, decoded, fields[]}` summary. That side is WP-S5's
  work package, not this bridge diff.

## Negative evidence (the --static contract, revert one thing at a time)

- the two sigs entries' `expect` changed: `sigcheck.py resolve --module soundsystem.dll` FAILs
  (shown in the WP-B report);
- the capture reading literal `p + 8` instead of the pin (a mutation of
  `bridge/mcp_bridge_game.inc`): `python3 -I bridge/test_sound_params.py --static --src <copy>`
  FAILs (shown in the WP-B report);
- the `plen = -1` clamp removed (a len above 65535 trusted): --static's clamp row fails;
- the params emission moved out from under the `ev->slot == SNVS_SOS_START_WITH_PARAMS` guard:
  the "params only for slot 11" row fails (the `\"params\":` writer text would no longer sit
  inside the slot-11 block);
- `BRIDGE_BUILD` left at m2.19: the version rows fail (and `control.capabilities` consumers that
  gate on the build would see the old bridge).
